# Evidence for individual historical-search claims

Use this rule when explaining the status of a named PhilPapers work after `pfm search`. It applies to the final rerun with the user's chosen filters and review files.

1. Save that run's complete stdout JSON in an ignored private path. If `--review-queue-file` was used, pair it with the queue from the **same run**. Do not combine a queue from an earlier run with a later result.
2. For each named work, locate its exact PhilPapers record URL in the original result's `items`, `unconfirmed_records`, and `year_review_candidates`. `scripts/audit_search_records.py` does this read-only check and rejects a queue with a different query time. Its output is a derived locator; cite the original result field as the basis of the conclusion.
3. Give the original result priority over the review queue. If the work is in `items`, call it an **已确认检索匹配** on the returned page. The audit helper's `review_queue.reasons: ["confirmed_type"]` only says the type-review queue also contains evidence for that work. Do not describe an `items` work as “仅属 type-review 支持”, “只确认了类型”, or still unconfirmed. A queue item with `reason: confirmed_type` **without** an `items` hit does not by itself establish a final search match.
4. `unconfirmed_records` supplies a stated unresolved reason; `year_review_candidates` supplies a year-review lead. If the work appears in none of the three result lists, say **"本次返回的逐篇记录中未定位到该作品，具体处理关口未由这些文件给出"**. Pagination can also leave a confirmed item off the returned page.
5. `stats.no_feed_year_hint`, `stats.unsupported_type`, and similar numbers describe groups, not members. Never infer a named work's exclusion stage from a group count, from the absence of its URL, or from a prose report written for an earlier run. Original publisher evidence may independently establish that a work is an editorial or a conference paper; label that as a **work-form finding**, not as a traced CLI exclusion reason.
6. Copy `total_matches` from the final result. Check source failures and the requested scope before calling the result complete. If a conclusion requires a gate that the JSON does not expose, mark the gate untraced and request or implement a per-record CLI trace; do not invent one.

Run `scripts/audit_result.py` as described in [audit-output.md](audit-output.md) before composing a full result report. It also supplies exact queue reason counts, identity pair indices, URL field presence, and all available source status fields. Search result entries use `source_urls`; queue entries use `record_url`. An absent `stable_url` is not an original JSON null. `year_review_pending` marks missing feed year hints without applicable publisher-year review. Do not describe it as proximity to a requested year boundary. Use both Wanfang cross-check and discovery status fields, and distinguish candidate totals from attempted checks. The older `audit_search_records.py` remains available for the narrower exact-URL check.

Example: if `GRUFUH` is in none of the three result lists, and its journal calls it an Editorial, report both facts separately: the journal establishes its work form; the available CLI output does not show which gate handled that URL.
