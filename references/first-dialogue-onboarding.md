# 首次对话与账户授权引导

状态：实现规则
规则版本：`0.1`
最后修订：2026-09-06

## 1. 目的

新用户第一次调用本 Skill 时，通常还没有兴趣画像。无论用户先问“怎么使用”，还是直接要求建立
自动周报，Skill 都必须尽早说明：监测范围来自研究者自己的研究方向，而不是一套对所有人通用的
论文排行榜。首次对话还应当给用户一个可选择的机会，决定是否用 PhilPapers／PhilPeople 的公开
账户资料辅助兴趣推理。

账户资料不是必需输入。用户拒绝、暂缓或没有 PhilPapers 账户时，仍然可以只凭自然语言研究描述
完成全部基本功能。

## 2. 如何判断是否是首次引导

在第一次实质性回复前，优先运行只读命令：

```powershell
.\.venv\Scripts\pfm.exe onboarding-status --config .\config\watchlist.yaml
```

该命令不打印研究方向原文或资料页 URL，只报告下列状态：

- 私人画像是否存在；
- 是否缺少研究方向；
- 是否尚未记录 PhilPapers 账户决定；
- 首次引导是否完成。

行为规则：

- 私人画像不存在：在同一轮询问研究方向和可选账户授权；
- 旧版画像已有研究方向，但账户决定为 `not_recorded`：只补问账户授权，不要求用户重复描述研究；
- schema 0.5 已记录 `declined`、`deferred` 或 `authorized_public_only`：不在以后每次对话重复询问；
- 用户随时可以主动修改或撤回原决定；撤回后不得再次读取账户资料。

不能用“Skill 已安装”“仓库目录存在”或“taxonomy 凭据存在”代替首次引导状态。这些事实都不能
证明用户已经提供研究方向或同意账户资料访问。

## 3. 首次回复必须包含什么

首次实质性回复应当同时包含两项内容，但可以继续回答用户原本的问题，不必只留下一个生硬表单。

第一，说明并询问研究方向：

> 为了建立真正与你有关的监测范围，我需要先了解你的研究方向。你可以用普通语言说明正在研究的
> 哲学家、文本、概念、问题、争论、传统或明确不想收到的范围；不需要预先知道 PhilPapers 标签。

第二，单独询问可选的公开账户授权：

> 你是否愿意提供自己的 PhilPapers／PhilPeople 公开资料页链接，并授权本 Skill 以只读方式分析
> 其中公开展示的自报研究兴趣？这完全可选；不提供不会影响基本功能。我不会要求密码、Cookie、
> API key，也不会访问私人页面。公开书目、待读清单和 My Works 如需使用，会再分别说明并征得同意。

可以依用户语言和上下文自然改写，但不得省略“可选”“只读”“公开资料”“不影响基本功能”以及
“不要求密码、Cookie、API key”这几个实质边界。

如果用户直接要求创建自动周报，可以同时解释后续步骤，但在取得研究方向并确认正式分类以前，
不能建立代表该用户的生产订阅、历史基线或定时任务。账户问题本身不是阻塞条件：用户明确拒绝或
暂缓以后，应继续完成纯文本兴趣建模。

## 4. 账户决定和授权范围

`onboarding.philpapers_account.decision` 只允许：

- `declined`：用户不授权使用账户资料；
- `deferred`：用户现在不决定；
- `authorized_public_only`：用户提供公开资料 URL，并授权至少一个明确范围。

允许的 `authorized_scopes` 是：

- `self_declared_interests`：资料页上由用户公开填写的研究兴趣或专长；
- `public_bibliographies`：用户明确指定的公开个人书目；
- `public_reading_lists`：用户明确指定的公开阅读／待读清单；
- `my_works`：公开显示的 My Works，仅作为可能的研究方向证据。

第一次笼统同意“查看公开资料”默认只足以继续询问资料页 URL和确认 `self_declared_interests`，不
自动授权其余三个范围。要使用公开书目、公开阅读清单或 My Works，应当说明各自含义并逐项取得
同意。

PhilPapers 官方说明 My Works 主要根据姓名和别名自动生成，归属可能不可靠。因此 My Works 只能
支持待确认标签建议，不能证明用户确实写过、读过或长期研究其中每篇作品。

## 5. URL 和访问安全

配置只接受不含凭据的 HTTPS PhilPapers／PhilPeople 资料 URL，并拒绝：

- HTTP URL；
- 其他主机；
- URL 中的用户名或密码；
- 非标准端口；
- query 或 fragment；
- 站点根目录或空路径。

用户说“同意”以后，仍需由用户主动提供资料 URL。Skill 不根据姓名在全站猜测哪一个账户属于
用户，不尝试登录，也不复用浏览器 Cookie。

私人书目不能因为用户授权读取公开资料页就被访问。如果官方流程要求用户先把私人书目设为公开，
Skill 不应劝诱或代替用户改变可见性；可以改为让用户导出、复制或概括愿意用于分析的内容。

PhilPapers taxonomy API ID／API key 只用于取得分类体系，不是账户资料授权。二者必须在概念、配置
和提示语中保持分离。

## 6. 账户证据如何影响标签

账户证据只用于理解或提出 `proposed_interest_set`，不能自行加入活动集合。

优先级仍是：

1. 用户当前明确描述和排除；
2. 用户已确认的历史兴趣配置；
3. 获得授权的公开自报兴趣；
4. 获得授权的公开书目或阅读清单；
5. 获得授权的 My Works；
6. AI 的有限哲学关系推理。

账户资料与当前陈述冲突时，应当询问用户，而不是用旧资料覆盖新陈述。每个账户推理候选仍须展示
来源、关系、范围和可能噪声，并由用户确认后才能进入实际周报。

## 7. 本地记录与撤回

schema 0.5 在 Git 忽略的私人 `config/watchlist.yaml` 中保存：

- 首次引导完成时间；
- `declined`、`deferred` 或 `authorized_public_only`；
- 决定记录时间；
- 用户主动提供的公开资料 URL；
- 明确授权的范围名称。

不保存密码、Cookie、会话令牌、恢复码或私人页面内容。`pfm onboarding-status` 不输出研究方向或
资料 URL。

用户撤回授权时，建立新的私人配置版本，清除资料 URL 和全部授权范围，并停止后续读取。是否删除
此前由账户证据产生、但尚未确认的候选，应当询问用户；已经由用户独立确认的活动标签不应在没有
用户决定的情况下自动删除。

## 8. 验收场景

- 新用户问“这个 Skill 怎么使用”：回答使用方法，同时询问研究方向和可选公开账户授权；
- 新用户说“帮我建立自动周报”：先取得研究方向和账户决定，再进行分类确认、基线和调度；
- 新用户没有 PhilPapers 账户：记录 `declined` 或 `deferred`，继续文本兴趣建模；
- 用户拒绝账户授权：不保存 URL，不建立任何账户访问范围，不重复施压；
- 用户只授权公开自报兴趣：不能读取 My Works 或公开书目；
- 旧版画像已有研究方向：只补问尚未记录的账户决定；
- 已完成 schema 0.5 引导：以后普通运行不重复提问；
- 用户撤回：清除 URL 和范围，停止再次读取。
