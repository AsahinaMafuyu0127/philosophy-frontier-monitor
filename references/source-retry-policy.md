# 数据源重试、限额与单次运行熔断政策

## 1. 目的与适用范围

本政策规定正式周报、漏周补跑和用户主动即时拉取怎样处理只读数据源请求失败。它适用于运行时的
PhilPapers 分类页／RSS、PhilArchive OAI-PMH、OpenAlex 和 Crossref 请求；不改变论文新近性、作品
同一性或兴趣分类交集标准。

PhilPapers taxonomy 的带凭据下载另有固定端点、禁止重定向、响应大小和浏览器导入边界。认证失败、
Cloudflare challenge 或非 JSON 响应不能通过普通自动重试绕过，因此仍按
[taxonomy 生命周期](taxonomy-lifecycle.md)处理。

重试的目的只是吸收很短的暂时故障。它不能把来源未收录变成已收录，不能增加用户的 API 配额，
也不能保证第三方服务在本次运行中恢复。

## 2. 可重试与不可重试错误

默认只自动重试：

- HTTP `408`；
- HTTP `429`；
- HTTP `500`、`502`、`503`、`504`；
- `httpx` 传输层错误，例如连接中断、超时或远端协议中断。

HTTP `400`、`401`、`403`、`404` 和其他非暂时客户端状态不自动重试。它们通常要求检查请求、凭据、
权限、端点或站点防护；反复发送同一请求只会增加负担。未经验证的重定向也不得当作成功响应。

返回 HTTP 2xx 但 JSON／XML 结构不符合约定时，属于响应契约失败，不自动重新请求。程序应报告
来源和结构错误，而不是把错误页或畸形响应解释为“没有论文”。

## 3. 有界退避

每个幂等只读请求默认：

- 最多尝试 3 次，包含第一次请求；
- 没有服务端等待提示时，按 1 秒、2 秒指数退避；
- 同一个请求的累计自动等待上限为 10 秒；
- 不使用无限循环；
- 不在一次交互运行中等待到次日额度重置。

HTTP `Retry-After` 可以是秒数或 HTTP 日期。只要它不超过剩余的 10 秒运行等待预算，程序就按该值
等待；如果它要求更长时间，程序不应早于服务端要求再次请求，而应立即停止本次来源请求并报告
`retry_after_seconds`。这不是“忽略 Retry-After”，而是拒绝在前台长时间阻塞，也拒绝违规提前重试。

OpenAlex 在 429 响应同时给出 `X-RateLimit-Remaining: 0` 和有效的 `X-RateLimit-Reset` 时，程序把它
识别为当日预算已耗尽，并把重置秒数作为安全重试时间。如果这些头缺失，只能写“瞬时限速或当日
预算耗尽”，不能臆断是哪一种。OpenAlex 当前官方说明 429 可能来自每日 credits 用尽或每秒请求数
过高，并建议指数退避；参见 [Authentication](https://help.openalex.org/api/authentication/) 和
[Error Handling](https://help.openalex.org/api/errors/)。

Crossref 的具体限额取决于请求池和请求类型。程序不硬编码一个可能变化的“每秒额度”，而是保持
串行逐篇查询、提供 `mailto`、读取服务端状态与等待提示并有界退避。参见 Crossref 官方
[Access and authentication](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/)
与 [Tips and tricks](https://www.crossref.org/documentation/retrieve-metadata/rest-api/tips-for-using-the-crossref-rest-api/)。

## 4. 单次运行熔断

书目服务在完成有界重试后仍失败时，本次运行对该来源打开熔断：

- 后续候选不再重复访问同一失败来源，避免多达 300 个默认逐篇候选各自触发三次相同 429 或 5xx；
- 已经存在的短期私人缓存仍可以读取，因为它不发起远程请求；
- 另一个独立书目来源仍可继续核验；
- 只有在剩余证据足以完成旧作检查与作品身份判断时才可推送；
- 仍依赖失败来源的候选标为 `old_work_check_incomplete`，不得冒充“查无记录”；
- 下一次周报、补跑或主动拉取重新建立新的运行级熔断状态，可以再次尝试来源。

永久性 HTTP 4xx 属于单个请求的非重试失败时，不得仅凭这一条就打开来源级熔断：当前候选保留为
`automatic_retry_required`，后续候选继续访问该来源。只有可合理说明来源整体暂不可用的 408、429、
选定 5xx、传输失败、超出本轮等待预算或响应契约失效，才停止本轮后续请求。若在若干单条 4xx 之后
又出现来源级失败，覆盖说明应以真正触发熔断的后一个失败为准。

即时模式的 OpenAlex DOI 批量请求失败后，不缓存这批 DOI 的“未收录”结论，也不继续发送题名批量
请求；它转入 Crossref 优先的有界逐篇退回。OpenAlex 恢复之前仍需要其证据的条目明确计入未完成
核验。批量失败不应使已经能由其他可靠证据确认的结果全部丢失。

正式周报同样使用每次运行独立的 Crossref／OpenAlex 熔断。书目来源失败会出现在报告来源覆盖中，
相应候选进入持久化待核验队列；但 PhilPapers 分类 feed 是兴趣分类证据的必要来源，任一配置 feed
在有界重试后仍失败时，整次正式运行保持失败并且不推进检查点。

## 5. 错误输出与隐私

可恢复失败至少包含：

- 受影响来源；
- 失败类别：传输暂时失败、HTTP 暂时失败、瞬时限速／预算不明、当日预算耗尽或永久 HTTP 状态；
- 已尝试次数；
- 停止原因：尝试次数用尽、服务端等待超过运行预算或不可重试状态；
- 安全可得时的 HTTP 状态和 `retry_after_seconds`；
- 检查点是否推进、覆盖是否完整以及候选是否进入待核验状态。

错误不得包含完整请求 URL、查询参数、题名、作者、RSS description、响应正文、API key、`mailto`、
Authorization、Cookie 或原始传输异常文本。原始异常可能把带 key 的 URL嵌入字符串，所以公开错误
只使用经过控制的结构字段。

## 6. 验收条件

- 503、502 等短暂错误后成功时，使用同一请求重试并返回成功结果；
- 短 `Retry-After` 被准确遵守；
- 长 `Retry-After`／OpenAlex 次日重置不会导致长时间睡眠或提前重试；
- 403 等永久状态只发送一次；
- 传输错误在第三次失败后停止；
- 错误文本不泄露 URL 或 key；
- 同一书目来源失败后，本次运行后续候选不再形成请求风暴；
- 失败结果不写入书目缓存；
- 周报与即时报告都明确标注书目来源覆盖失败。

## 7. 运行前诊断与脱敏遥测

`pfm doctor --live` 是只读探测，不建立基线、不写缓存、不推进周报检查点，也不记录论文内容。它对
PhilPapers、PhilArchive、OpenAlex 与 Crossref 分别执行 DNS、TLS、HTTP／响应合约检查，避免把
“域名解析失败”“证书校验失败”“服务端状态错误”和“返回结构改变”混成一句笼统的“网站不可用”。
可以用重复的 `--source` 只检查指定来源。

每个正式 CLI 运行汇总以下网络事实：逻辑请求数、第一次即成功数、重试后成功数、失败数、实际
尝试次数、自动等待秒数、因长 `Retry-After` 推迟数，以及运行级熔断后跳过的后续查询数。遥测只
保留服务端限额头中可安全解析的非负数字，不保留 URL、查询参数、题名、作者、正文、key、邮箱或
底层异常文本。

OpenAlex 剩余额度只有在服务端明确返回可解析响应头时才可报告。若用户已经有宽范围操作的预计
请求数，可由 `doctor --live --source openalex --expected-openalex-requests N` 比较；剩余额度不足时
必须提醒缩小范围或等待重置，响应头缺失时则报告“未知”，不得把未知解释为额度充足。
