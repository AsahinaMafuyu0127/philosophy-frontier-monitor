# 官方公众号公开发现与核验

适用范围：`pfm journal-watch wechat-discovery-plan` 列出的刊物。目前仅有《现代哲学》与《哲学动态》的账号名称和已读原帖可作为身份对照起点。计划命令只读取本地目录，不访问网络，也不代表已发现新帖。

## 在 Skill 调用中执行

用户要求 `search`、`pull-now` 或周报时，先运行 `pfm journal-watch wechat-discovery-plan`，然后对计划内与本次范围有关的刊物进行一次有界公开发现。无需用户提供单篇原帖链接。可用普通网页搜索或交互式浏览器，在每刊一次检索中结合账号名、刊名、目标年份／期号和“目录”查找**确切原帖 URL**。已读原帖只用于核对账号身份与发现入口，不作为新一期的证据。搜索结果缺失不表示该账号没有发帖。

找到候选后在交互式浏览器打开原帖，核实页面确属 `mp.weixin.qq.com`、账号显示名、原帖日期、刊名、年份期号、完整可见的目录正文，并同已核账号或刊方入口交叉核对。若用户只要求期次线索，至少须有可归属该期的原帖内容；若要记录逐篇题名，还须逐项读取。账号同名、搜索摘要、转载、图片缩略图、HTTP 200、验证页或正文残缺均不足以核实。遇到验证或登录阻断即记 `blocked`，不尝试绕过验证。网页搜索返回的发布日也不能代替原帖日期。

复核通过后，按精确 URL 与显式日期执行 `pfm journal-watch observe --journal … --year … --issue … --evidence-url … --evidence-kind official-wechat --announcement-on YYYY-MM-DD --status reviewed --confirm-evidence`。只有原帖明确给出月份时才传 `--label-month`；不得从期号推算。原帖日期只是公告日。把发现 URL、账号核验、全文可读情况与限制保留在 Git 忽略的本地观察记录。同一期按期次去重，多个官方渠道的 URL 仍各自留痕。完成这一步后再运行用户要求的 `search`、`pull-now` 或 `weekly-run`，这些命令才会读取本地已复核期次。

## 无人值守边界

本地 `pfm search`、`pull-now`、`weekly-run` 和 Windows 定时任务本身不具备公众号文章列表授权，也没有可依赖的微信原帖正文接口；它们只读取已复核的本地证据。上述公开发现是 Codex Skill 在具备搜索和可读原帖的会话中执行的前置步骤，不承诺每次运行均能得到新帖。不能把需要登录或验证码的交互变成定时爬取。若前置步骤无法完成，继续运行请求的模式，并说明该刊公众号覆盖未核实，不填入周报的刊方期次或逐篇日期。

截至 2026-10-14 的可访问性核查：微信公开专辑页一次性展示过《周易研究》帖名和原帖链接，但普通 HTTP 打开其中一篇转至验证页，正文未取得；微信和搜狗微信搜索的公开 `robots.txt` 不允许把相应路径作为无人值守采集入口。故该专辑不在自动发现计划中。正式的公众号发布记录接口需要相应账号的授权；项目目前没有这些期刊账号的授权。若以后取得获授权的服务，须先验证接口许可、账号归属、正文范围、限额与失败状态，再另行接入。
