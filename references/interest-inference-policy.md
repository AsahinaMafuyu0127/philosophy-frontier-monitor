# 兴趣标签有限推理政策

状态：第 1 阶段顶层设计
规则版本：`0.2`
最后修订：2026-09-06

## 1. 目的

研究者不应当被要求先掌握 PhilPapers 的完整分类体系，才能说明自己的研究兴趣。尤其对刚进入
某一领域的研究生而言，“我研究柏拉图的知识论”已经是有效输入；系统应当帮助他发现这句话可能
涉及的文本、问题、历史接受和当代问题分类。

这种帮助属于兴趣解释，不属于论文评价。AI 可以推理“用户还可能希望监测哪些受控分类”，但不
可以判断哪些论文更好，也不可以让未经确认的推断静默改变每周推送范围。

## 2. 两个集合，而不是一个集合

兴趣建模必须区分：

```text
C = confirmed_interest_set     用户已经确认、实际用于订阅与匹配的分类
S = proposed_interest_set      AI 有理由提出、但仍等待用户决定的分类
```

每周运行只使用：

```text
notify = confirmed_new AND (C ∩ paper_categories != empty)
```

`S` 不建立 feed、不进入集合交集、不改变周报结果。用户接受某个候选后，该分类从 `S` 移入新版
`C`，兴趣配置版本加一；用户拒绝或暂缓时保存决定，避免以后反复提出同一建议。

这是不可放宽的边界。taxonomy 核验只能证明“这个分类真实存在”，不能证明“用户确实希望收到
这个分类的全部新论文”。

## 3. 不判断用户是新手还是专家

系统不根据学历、行文风格或术语多少给用户贴上“初学者”“成熟研究者”标签。需要判断的是当前
这段研究描述是否足以确定监测范围，而不是判断说话者的学术身份。

默认使用 `adaptive` 模式：

- 如果描述只给出人物、领域或宽泛主题，启动探索性候选推理；
- 如果描述给出具体文本、段落、命题、争议双方、比较关系或明确排除项，优先按原文建立较窄
  的候选集，不额外扩张到整个学科；
- 即使描述很具体，也仍执行别名解析、taxonomy 核验和必要消歧；“不启动扩张推理”不等于不做
  任何语言理解；
- 用户可以随时明确选择 `minimal` 或 `exploratory`，覆盖自适应判断。

三种模式的含义：

- `minimal`：只处理明确提及、强语境蕴含和必要消歧；
- `adaptive`：根据当前描述的确定程度决定是否提出有限扩展；
- `exploratory`：系统化展示多个研究维度，但仍不自动确认任何扩展标签。

## 4. 推理的五种关系

每个推理候选必须标明关系类型。没有关系说明的“可能相关”不足以成为候选。

### 4.1 `directly_implied`

用户没有说出正式分类名，但研究描述直接蕴含该分类。例如“柏拉图关于知识的学说”可以提出
`Plato: Epistemology`。

### 4.2 `primary_text`

由用户明确提到的作品、篇章或语料得到。例如《泰阿泰德》对应 `Plato: Theaetetus`。

### 4.3 `conceptual_adjacency`

研究问题通常要求同时处理的概念关系。例如柏拉图知识论可能涉及 `Plato: Definition`、
`Plato: Knowledge and Belief`、`Plato: Perception` 或 `Plato: Forms`。这种关系必须逐项解释，
不能把人物分类的所有后代一次性包装成“推理结果”。

### 4.4 `historical_reception`

用户明确关心发展、影响、接受或批判时，可以提出跨人物、时期或传统的分类，例如
`Plato and Other Philosophers` 或某个具体哲学家的柏拉图相关分类。仅仅研究柏拉图知识论，不
自动蕴含用户希望收到整个 `History of Western Philosophy` 的论文。

### 4.5 `contemporary_bridge`

用户关心古代问题与当代讨论之间的关系时，可以提出当代分类。例如研究《泰阿泰德》的“真信念
加说明”与 JTB 的关系，可以提出 `Defining Knowledge`、`The Gettier Problem`、`Justification`
等真实分类。只有用户表达了这种桥接兴趣，或者在探索模式中明确把它作为可选方向展示，才提出
这类候选。

`methodological_context` 用于解释方法论兴趣，例如文献学、解释策略、分析哲学方法或比较方法；
只有方法本身是用户关注对象时才提出，不能因为系统使用了某种方法就加入。

## 5. 候选生成步骤

1. 忠实保留用户原始描述；
2. 提取人物、文本、概念、问题、关系、传统、时期、方法和排除项；
3. 识别用户已经明确说出的分类与强语境映射；
4. 判断当前描述是否留下会显著影响召回范围的空缺；
5. 只沿与原文有可说明关系的维度生成候选；
6. 在当前完整 taxonomy 中核验每个候选的 ID、规范名称和层级位置；
7. 删除无法核验、仅由词语联想产生或范围失控的候选；
8. 为每个保留候选说明关系、依据、可能增加的范围和潜在噪声；
9. 将候选与已确认标签、已排除标签和历史拒绝项对照；
10. 用普通语言询问用户接受、拒绝还是暂缓，不要求用户编辑 YAML。

模型可以生成用于检索 taxonomy 的自由概念，但这些自由概念本身永远不是正式标签。只有解析到
当前快照中的真实分类 ID 后，才能成为 `S` 中的候选。

## 6. 推理停止条件

满足下列任一条件时停止继续扩张：

- 下一步只能依靠一般联想，而不能说明与用户问题的研究关系；
- 候选只是一个极宽祖先分类，无法说明用户为何需要其全部论文；
- 需要猜测用户的学术立场、研究方法或历史兴趣；
- 候选与已有分类高度重叠，却没有独立增加召回的理由；
- taxonomy 中没有对应分类；
- 用户已经明确排除或拒绝；
- 继续推理需要读取未获授权的私人账户数据。

候选数量不是越多越好。默认先展示少量、关系不同且能改变召回范围的候选；必要时允许用户要求
第二轮扩展。

## 7. 证据来源及强度

证据按以下次序理解，但不能用低层证据覆盖用户当前的明确表达：

1. 用户当前明确描述、明确排除和明确确认；
2. 用户此前确认的兴趣配置及变更决定；
3. 用户明确授权使用的 PhilPapers 自报兴趣领域或公开个人书目；
4. 用户明确授权使用的待读清单；
5. 用户资料中的 `My Works`；
6. AI 基于哲学关系和 taxonomy 结构提出的推理。

这些来源的语义不同：

- 自报兴趣领域较直接，但可能过时；
- 个人书目通常反映整理过的兴趣，但某个书目也可能只是课程或一次性项目；
- “to read”表示保存为待读，不证明已经阅读，更不证明长期研究；
- `My Works`可能反映研究方向，但 PhilPapers 说明它主要由姓名匹配自动生成，归属并不总可靠；
- 浏览或点击历史既没有在当前官方 API 文档中形成可用契约，也不应被当作默认授权数据源。

因此账户资料只用于提出或加强候选理由，不能单独把分类加入 `C`。

## 8. PhilPapers 账户访问边界

- 只有用户主动提供资料地址并明确同意用于兴趣建模时，才读取公开资料；
- 私人资料、私人书目或待读清单不能因为本机已有 taxonomy API key 就自动访问；taxonomy API key
  不等于读取私人账户数据的普遍授权；
- 不要求用户把 PhilPapers 密码、Cookie、恢复码或会话令牌交给本项目；
- 官方“嵌入私人书目”流程要求用户先把该书目设为公开。不能为了方便而替用户更改这一隐私状态；
- 用户可以选择导出、复制或概括其书目，由本地会话分析；只保存标签推理所需的最小证据；
- 账户证据的来源、取得时间和可见性必须记录，用户撤回授权后停止再次读取；
- 不进行批量抓取或绕过登录限制。

首次对话必须主动询问用户是否愿意提供公开资料页，并说明这不是使用监测功能的前提。笼统同意
查看公开资料默认只覆盖公开自报兴趣；公开书目、公开阅读清单和 `My Works` 必须分别说明并记录
授权范围。已完成的决定不得在以后每次对话重复追问。完整触发、记录和撤回规则见
[首次对话与账户授权引导](first-dialogue-onboarding.md)。

## 9. 向用户展示候选

候选不使用不可解释的相关性分数。建议格式：

```yaml
category_id: "74844"
category_name: "Plato: Knowledge and Belief"
relation: "conceptual_adjacency"
rationale: "你的研究对象是柏拉图知识论；知识与信念的区分是该问题的直接组成部分。"
evidence_sources:
  - "user_text: 柏拉图的知识学说"
  - "taxonomy: child of Plato: Epistemology"
breadth_note: "比 Plato: Epistemology 更窄，主要增加知识与信念关系的论文。"
status: "pending"
```

用户可以回答“都加入”“只加入第 1、3 项”“第 2 项以后再说”或“都不要”。系统负责把自然语言
决定转换为配置更新，不要求用户自己操作 category ID。

## 10. 柏拉图知识论示例

输入：

```text
我研究柏拉图的知识论，关注《泰阿泰德》和《巴门尼德篇》，也关心后世发展与当代知识论的关系。
```

较强的核心映射：

- `Plato: Epistemology`（74810）；
- `Plato: Theaetetus`（74924）；
- `Plato: Parmenides`（74915）。

应当向用户说明后再决定的候选：

- `Plato: Knowledge and Belief`（74844），概念邻接；
- `Plato: Definition`（74843），知识定义问题；
- `Plato: Forms`（74832），只有当用户认为理念论是其知识论研究的必要组成时加入；
- `Plato and Other Philosophers`（74817），历史接受与比较，但范围可能较宽；
- `Defining Knowledge`（5481），当代桥接；
- `The Gettier Problem`（5483），只有用户关心 JTB／Gettier 路线时加入；
- `Justification`（5398），范围宽，必须提示可能带来大量与柏拉图无关的论文。

不应仅因“关心哲学史”就自动加入整个 `History of Western Philosophy`。更好的办法是先询问用户
关心哪些接受关系，或选择 `Plato and Other Philosophers` 以及具体哲学家相关分类。

更精细的输入：

```text
我关心《泰阿泰德》关于知识的第三个定义，即 true belief with articulation，是否是分析哲学
JTB 理论的前身，以及二者的差别。
```

此时不需要启动无边界的探索。候选可以集中在：

- `Plato: Theaetetus`；
- `Plato: Definition`；
- `Plato: Knowledge and Belief`；
- `Defining Knowledge`；
- `The Gettier Problem`；
- 必要时询问是否加入较宽的 `Justification`。

“描述精细”改变的是推理范围，不改变用户对候选的最终决定权。

## 11. 配置和版本语义

- `confirmed_categories` 是唯一活动集合；
- `proposed_categories` 保存 `pending`、`deferred` 或 `rejected` 候选，不建立 feed；
- 候选被接受时移入 `confirmed_categories`，删除或保留一条决定历史，并增加兴趣配置版本；
- 新版本记录带时区的 `effective_from`，以便普通运行和漏周补跑判断版本边界；
- 新配置默认只影响以后周次；历史回溯另行运行且标为 `backfill`；
- AI 重新推理不能覆盖用户之前的拒绝、排除或粒度选择；
- taxonomy 更新后，候选和确认标签都必须按 ID 重新核验。

## 12. 验收要求

- 宽泛输入能够得到分层、有理由的候选，而不是只有字面标签；
- 精细输入不会被自动扩大到整个哲学史或整个认识论；
- 所有候选都是真实 taxonomy 分类；
- 推理候选在用户确认前绝不参与 weekly-run；
- 每个候选都有关系类型、理由、证据来源和范围提示；
- 账户资料只能在授权范围内使用，并保持其真实语义；
- 用户拒绝的候选不会在下一轮无理由重复出现；
- 确认候选会生成新版兴趣配置，不改写旧版本。
