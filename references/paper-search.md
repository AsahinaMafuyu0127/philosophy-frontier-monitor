# 根据兴趣配置检索已有论文

## 用途与入口

用户要求“按我的兴趣找论文”“用已确认标签查已有研究”或“按引用量排列”时，运行独立的
`pfm search`。它复用私有 watchlist 中的已确认分类、子类展开标志和排除集合；不使用未确认
的候选标签，不运行周报补发，也不要求 baseline。只有缺少研究方向／已确认分类时才需要先完成
标签映射；已有兴趣配置不因可选账户授权尚未记录而被阻塞。

检索不限制为最近七天，旧论文可以进入。不要用 `pull-now --days 31` 代替历史检索。
用户要求不按年份、只按 feed 标签检索时，不传年份边界，不补设“近五年”等时间窗；默认交付
本次能够取得并确认的全部匹配论文，不因方向较窄而减少候选或只选高被引论文。

在 skill 根目录执行；Windows 示例：

```powershell
.\.venv\Scripts\pfm.exe search --config config/watchlist.yaml
.\.venv\Scripts\pfm.exe search --config config/watchlist.yaml --year-from 2000 --limit 30
.\.venv\Scripts\pfm.exe search --config config/watchlist.yaml --category 74924 --work-type article
.\.venv\Scripts\pfm.exe search --config config/watchlist.yaml --category 74924 --category 74915 --match all
```

分类 ID 仅为语法示例，不能假定用户已经选择它们。先在当前配置和 taxonomy 中核验用户所说的
标签，再传入相应 ID。命令默认读取全部已确认兴趣；`--category` 可重复，只对本次选择配置范围
内的分类。超出当前兴趣范围的分类需要先准备另一个经用户确认、feed 已核验的检索配置文件，
通过 `--config` 指定；不要改写长期订阅配置来完成临时查找。

## 匹配、范围和论文类型

- 默认 `--match any`：命中任一所选标签；`--match all`：每个所选标签至少有一个命中。
  一个配置为展开子类的父标签作为一个分类组，命中该组任一成员即满足该标签，不能要求论文
  同时属于该父分类的所有子分类。
- 分类证据来自已配置 feed 的成员关系。读取所有已配置 feed 后合并同一来源记录，再按共同
  DOI／OpenAlex ID 合并已确认的重复作品；在合并后的成员集合上处理交集和排除。
- 此入口覆盖 **PhilPapers 分类 feed 本次实际返回的记录**。不能声称完整历史书目、全领域
  最高引用榜或全站搜索；不能拿 OpenAlex 主题、关键词相似度替代 PhilPapers 分类证据。
  未读取的其他分类、源端截断或显示过滤可能影响成员及排除判断，报告必须保留这一限制。
  如果存在不在所读 feed 集合中的排除分类，提示无法完整核验这些排除项。
- **有年份范围时**：合并同一 feed 来源记录后，没有 feed 年份提示的记录直接排除，在
  OpenAlex／Crossref 查询及候选预算检查之前完成。即使有 DOI、feed 到达时间或手稿标记，
  也不为这类记录补查或交给用户确认。跨所读 feed 的同一记录已有年份提示时可继续常规筛选。
- **不限制年份时**：不要求 feed 日期、feed 年份提示或正式发表日期；按标签成员关系和论文
  类型、身份正常核验，纳入全部已确认匹配论文。日期缺失本身不排除，也不为补日期发起请求。
- 只纳入[现有论文类型](work-type-policy.md)：期刊论文、综述论文、会议论文、预印本、手稿等。
  书籍、书章、书评、学位论文、辞典条目及其他非论文形式排除。不因题名主题判断类型；未知、
  不支持或冲突的类型均不能以默认 `article` 放入结果。未确认项仅提示其存在，不报告数量。
- `--work-type` 可重复以进一步限定支持的论文类型。`article` 只选择该规范类型；若用户需要
  同时包含综述，可另加 `--work-type review-article`。
- `--year-from`／`--year-to` 为包含端点的书目年份筛选。年份来自匹配的 OpenAlex／Crossref
  日期证据；不把 feed 时间或描述中抽取的年份提示当正式日期。
  无年份筛选时保留缺少正式日期的论文并标注缺失；有年份筛选时不把未知年份混入范围内，
  只提示有此类日期缺失，不显示数量。

## 引用量与输出

OpenAlex 的 `cited_by_count` 仅作为可选展示数据。整数且非负才是有效值，零是有效值；缺失、
负值、布尔值或格式异常都是未知。有数据的论文按引用量降序排列，缺失置后并明确写“缺失”。
相同引用量按年份降序、题名和来源链接稳定排列。缺失数据本身不会排除论文，不为单纯补引用量
增加逐篇请求，不合并不同平台的数字，也不将重复版本的引用量相加。

同题名出现多个不能唯一确定的 OpenAlex 作品时，报告书目身份未确认，不随意选择引用量最大的
版本。引用数据带来源、来源记录 ID 和取得时间，不构成论文质量或阅读价值的判断。

CLI 返回 JSON，包含结构化 `items` 与中文 `report_markdown`，可由后续网站入口复用核心函数
`run_paper_search` 的相同结果。每条有题名、作者、年份及来源、论文类型证据、匹配分类、引用
数据和 PhilPapers 原始链接。`total_matches` 是本次已核验匹配数，不能当作数据库全部命中数。

报告只说明存在论文类型或书目身份尚未确认的记录，不展示未确认数量、补查延期数量或候选
核验统计。JSON 中的 `stats` 是内部诊断数据，skill 在答复、摘要或另行生成的报告中也不得
转述这些未确认数字。已确认论文总数、引用量及其缺失统计仍可正常展示。

`unconfirmed_records` 仅保留本次已有的题名、来源链接和未确认原因；报告可折叠提供这些材料，
不编号、不标注总数，也不要求用户必须处理。可用表述：

> 存在论文类型或书目身份尚未确认的记录，未纳入论文结果。如有需要，可根据原始来源自行核对。

交付报告即完成本次检索。skill 不为这些未确认记录再启动检索、另换数据源继续调查、提高预算
或安排后续核验。用户自行确认是可选事项，无需向 skill 提交结果。有年份范围时，因没有 feed
年份提示而排除的记录不属于这一自行核对范围。不限制年份时，缺日期但类型或身份未确认的
记录仍可提供已有来源供自行核对。已有旧报告没有保留未确认记录明细时，只更新存在性提示，不为补齐
清单重新联网，也不凭数量推造条目。

不限制年份且未指定 `--limit` 时，默认返回全部已确认匹配论文；有年份范围时默认显示 20 篇。
仅在用户明确要求限量或分页时，为不限年份检索设置 `--limit`／`--offset`；不能把默认截取的
一页称为全部结果。完整结果较长时可交付文件，不通过删减论文来缩短报告。
`--limit` 控制数量，`--offset` 控制偏移，`next_offset` 指示后续结果。
统计中的引用缺失数针对全部已核验匹配结果，不能误说成仅本页缺失数。重新调用会重新查询，
源端变化可能影响跨次分页；一次调用的结构化结果可由调用者在内存中分页。

## 请求边界与状态

默认最多 1000 个候选、100 次 Crossref 补充书目核验。候选超限会在书目查询前明确失败；
`--limit 20` 只限制展示条数，不减少待核验候选。要减少工作量先缩小分类范围；年份和类型过滤
需要书目证据；仅在有年份范围时，缺少 feed 年份提示的记录在此之前排除，不占候选预算。
不限制年份时保留这些候选，候选超限仍明确失败，不以悄悄跳过无日期记录来满足预算。
只有用户要求扩大范围时才提高 `--max-candidates`
或 `--max-fallbacks`。可用 `--max-fallbacks 0` 禁用逐篇补充核验。

先按 DOI 和题名分批取得 OpenAlex 书目；仅在缺少类型证据或筛选所需年份时才尝试有预算的
Crossref 退回。来源限流／响应错误沿用有界重试和来源熔断，已取得的论文证据仍可使用，引用
缺失仍按缺失显示。任一所需分类 feed 失败时不返回“零篇且完整”的成功结果。

进度只输出阶段和数量。此模式不打开／写入周报 SQLite、OAI 缓存、书目缓存或 watchlist，
不下载全文，不写报告文件。JSON 输出本身包含用户选定标签及论文，应作为用户私有结果处理。
不要对未知类型或预算内未核验的候选宣称“不是论文”或“没有相关研究”。

## 数据源依据

- [PhilPapers RSS FAQ](https://philpapers.org/help/faq.html)：从分类等结果列表生成 feed。
- [PhilPapers JSON API](https://philpapers.org/help/api/json.html)：公开 taxonomy 接口；有限子集
  的完整 article feed 需向提供方联系申请，因此此版本不假定拥有完整历史书目接口。
- [OpenAlex citation semantics](https://help.openalex.org/data/works/citations/)：
  `cited_by_count` 统计 OpenAlex 匹配到的引用。
- [OpenAlex sorting](https://help.openalex.org/api/sorting/)：引用数可以按降序排列；本项目对
  由 PhilPapers 分类确定的已核验候选在本地排序。
